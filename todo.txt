Partner Center submission.  That submission is the whole item.  The Store is on
1.0.23, which serves the v1.4.5 catalog, so every Windows user today runs the R8
that erases every matching CP/M file when a host filename holds ? or *.

  Submit 1.0.25, not 1.0.24.  Both carry the v1.4.12 repin and both were
  verified at the artifact, but 1.0.24 was packaged before build-msix.ps1 kept
  the Store arm's symbols and no .pdb for it exists anywhere, so its crash dumps
  would be unreadable the way 1.0.22's are.  1.0.24's package is kept as
  dist\z80cpmw-1.0.24-store.msix; delete it once 1.0.25 is submitted.

- 1.0.25 makes a superseded disk image visible and does not yet make it go away.
Two pieces are missing, and CHANGELOG [1.0.25] has the design behind both:

  * Nothing calls downloadDisk() for a DiskRefreshPlan::RefreshNow.  The caller
  has to be the UI rather than DiskCatalog, because isMounted is MainWindow's
  fact - replacing a file the running machine holds in a slot undoes itself on
  the next flush.  Wants an Update button beside Download and Delete.

  * A user who never opens Settings is never told.
  downloadAndStartWithDefaults() loads what diskFileLooksComplete() finds and
  never fetches the catalog, so a boot notice means a network fetch at every
  launch - a real behaviour change, to decide rather than assume.

  MainWindow.cpp and SettingsDialogWx.cpp are in no suite and cannot be, so both
  are verified by driving the built app.  See WIP.md.
