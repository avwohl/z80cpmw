The previous edition of this file was written on a Mac and gathered the work
that needed a Windows machine.  That pass has now happened.  The tree builds,

Still needs a Windows machine
------------------------------

- the console bugs cpmemu found and cannot fix from POSIX are still open.  They
are cpmemu's, not this repo's - both live in cpmemu/src/os/windows/platform.cc,
which z80cpmw compiles nothing of - but they are Windows console bugs and
whoever has the machine can do them at the same time.  cpmemu/todo.txt has the
measurements.  In short: (a) read_one_key() takes a 0x00/0xE0 byte from _getch()
as a special-key prefix and uses _kbhit() as the tie-breaker, which code page
437 loses intermittently and code page 65001 loses always; the fix is to read
INPUT_RECORDs with ReadConsoleInputW, which removes the guess rather than
narrowing it, and it forces five secondary changes (key-down filter, repeat-count
expansion, UTF-16-to-bytes conversion, re-keying extended_keys[] from CRT scan
codes to VK plus a ctrl flag, and widening the two-slot queue).  (b) ctrl+break
leaves the console in raw mode, because the default handler ends the process
without running atexit; one SetConsoleCtrlHandler beside the existing
atexit(disable_raw_mode) fixes it, mirroring os/linux/platform.cc's install loop.

- cpmemu's tests/win_console.cc cannot inject a non-ASCII character and cannot
send a console control event, so neither bug above has a regression test.  Both
are small additions to the harness.

- cpmemu's tests/run_tests.sh skips two cases for want of this platform -
"windows cross-compile" and "windows console".  Running it here turns 59
passed / 4 skipped into a real result.

- nobody has pressed the keys.  cpmemu's win_console.cc is faithful from the
console inward and steps past the terminal program itself: if Windows Terminal
binds ctrl+left for its own use the test still passes and the user still loses
the key.  The harness has a --manual mode - one pass in Windows Terminal, one in
a legacy conhost window.  Its POSIX twin wants the same in Terminal.app and
iTerm2, which is also not done.

The disk images are behind the core
------------------------------------

- the bundled hd1k images still carry the pre-98eb6a1 w8.com, so W8 cannot take
a host path however capable the Windows backend is.  Fixing it means either
refreshing the images from romwbw_emu/disks and cutting a new ioscpm release for
the catalog to point at, or repinning DiskCatalog.cpp's RELEASE_TAG at a release
built from the current disks.  docs/FILE_TRANSFER.md documents the behaviour the
new w8.com will have, not the one the shipped images do - see the doc item.

- upstream added disks/verify_disk_utils.sh for exactly this drift - it checks
that the R8/W8 inside the shipped images match their source.  Nothing under
packaging/ runs it, or anything like it, before a release.


Terminal residue - the other half of row 13
--------------------------------------------

- FEATURE_PARITY item 13 marked this repo partial for two reasons.  One is now
fixed: clear() no longer resets the attribute and the escape state on ESC[2J.
The other stands - there is no per-cell attribute beyond the packed CGA byte.
TerminalCell already carries unpacked foreground and background, so the gap is a
flags byte for bold / underline / blink / reverse plus the multi-HFONT paint
path to render them.  Roughly a day, and it splits cleanly into a parser commit
and a rendering commit.  The conformance suite is in the repository now, so a
regression in any of it would be caught.


Features the sibling ports have and this one does not
------------------------------------------------------

- the seven remote help topics have no bundled copy and no on-disk cache, so an
offline user - or a release whose assets were not attached - gets none of them.
ioscpm gained the offline fallback in its build 51.  The order to mirror is
download, then cache, then the copy shipped in the binary.

- a mistyped config key is silently absorbed, and then silently deleted on the
next save.  cpmemu fixed the same class of thing in bb03afa; the two places here
are Config.cpp's from_json and Keymap.h's KeyMap::build.

- Reset reboots the machine with no confirmation, and with "ctrlRToCpm": false a
single Ctrl+R does it.  Both mobile ports ask first.

- the terminal bell is unconditional; cpmdroid made it a setting.

- rebinding a key means closing the app and hand-editing JSON.  There is no
keyboard section in Settings.  Worth more now that the key map understands
modifiers and so has more to say.

Small things a review of the sync round raised and did not take
---------------------------------------------------------------

None of these is a regression; each was measured and left deliberately.

- a 0-byte disk image is accepted and mounts as an empty disk rather than being
refused with an error.  The shared emu_io_common.cc does the same, so fixing it
here alone would be a divergence; better done in both.

- MainWindow::startEmulator() clears the terminal, which erases the ROM-failure
text the ROM-loading path went to some trouble to print.  Pre-existing, and only
visible when a ROM has already failed to load.

- the four scrollback combinations (Shift+PageUp/PageDown, Ctrl+Home/End) are
intercepted before the key map, so a config that binds them is silently
ignored rather than refused.  docs/CONFIGURATION.md now says which four they
are; making build() reject them would be better still.


Loose ends
-----------

- romwbw_emu's hbios_dispatch.cc emits six C4267 warnings under MSVC at /W3.
Checked, all six: a size_t loop index promoting a uint16_t guest address, where
the truncation to sixteen bits IS the Z80 64K wrap HBIOS wants.  Nothing to fix,
and they are suppressed for that one imported file so a real warning is not
buried.  Worth a matching cast upstream if romwbw_emu ever turns the warning on
for itself - cpmemu's 9fee3c2 sweep for this class did not reach this file.

- there is no .pdb for the shipped 1.0.22 build, on any channel.  The symbols
are gone - a rebuild against wxWidgets 3.3.3 is a different binary - but
build-msix.ps1's -Beta branch should copy one out from now on.

- upstream's emu_io_common.cc uses rename() to replace the target in
emu_file_save().  ISO C leaves that undefined when the target exists and both
the MSVC CRT and mingw's msvcrt fail it outright, so the shared copy has a
dormant bug on Windows that this port does not (it uses MoveFileEx).  Worth a
shim in romwbw_emu beside the emu_fseek/emu_ftell one 573c7cc added.

- the v1.0.22-beta GitHub release is flagged Latest rather than prerelease,
unlike 1.0.16 / 1.0.17 / 1.0.21.  A judgement call, not a defect: if the -beta
channel should stay a prerelease, `gh release edit v1.0.22-beta --prerelease`.
